Geomorphon-guided tuning: what helps, what does not, and one conflict

Built tools/proc_model.py, a Python mirror of the mod's procedural generator, so a parameter change can
be scored in seconds (the geomorphon distribution included) instead of a 90 s server run. It also
implements the two candidate fixes: a smooth union (k) and concave hollows carved on the flanks.

Measured against the reference's geomorphon distribution (radius 30, flat tolerance 2), summing the
absolute differences of ridge/hollow/valley/footslope/spur:

    variant                              ridge   hollow  valley   spur    error
    current (detail 5)                    0.93    4.75    0.25    4.39    2.32
    detail 1                              1.65    4.67    0.28    4.19    1.91   <- best
    smooth union k=0.10                   0.35    6.47    0.20    3.60    5.66
    smooth union + hollows                0.43    6.50    0.18    3.26    5.96
    longer ridge segments (400-600)       0.21    5.33    0.25    4.86    3.70
    reference                             2.40    4.53    0.26    4.61       -

Findings:
* Smooth union -- the fix that should have removed the "valleys between domes" -- works (valley 0.25
  -> 0.20) but destroys the ridge class (0.93 -> 0.35). Net worse. Rejected.
* Longer ridge segments also destroy ridges, so crest length is not the lever.
* The one lever that works is the *detail amplitude*: it was masking the crests, and dropping it from 5
  to 1 raises the ridge class by 78% and halves the error.

The conflict worth recording: the slope-percentile and ridge-density metrics want detail 5 (that is
what made ridge density 278/km2 match), while the geomorphon metric wants detail 1. One parameter
cannot satisfy both, which is why the fitting has been oscillating between "too smooth" and "too
broken". The objective needs the geomorphon term added explicitly and the trade-off chosen on purpose.
